| ID | 问题 | 阻塞条件 |
|---|---|---|
| I1 | 实现是否满足 spec 的每个条款，包括测试没有覆盖、或只做了最弱断言的部分（见 tests/acceptance/eg_s2/NOTES.md）？ | 合理输入下实现的行为违反某条款原文（D-013 只保证测试覆盖到的部分） |
| I2 | 实现者对 spec 未定处的取舍（见账本"实现者对未定处的取舍"）是否与 spec 文字和决定一致？是否有取舍实际上碰到 D-008 触碰面（公共 API、持久化格式等），应作为 spec 缺陷交用户决定（D-011、D-017）？ | 取舍与 spec 或决定冲突；或属于实质选择却被实现者自行决定 |
| I3 | 每个错误实现补丁是否忠实于 spec 中该错误实现的文字描述，而不是更容易被抓住的其他错误（D-013）？ | 补丁不忠实，使"测试能挡住该错误实现"的证据不成立 |
| I4 | 验收测试是否只断言 spec 规定的行为？是否有测试断言了 spec 未规定的细节，会把另一个合理实现判错（D-013、D-014）？ | 测试越界断言，迫使实现采用 spec 未规定的特定选择 |
| I5 | 是否遗漏失败路径或输入边界：合理输入下实现会崩溃、给出错误的退出码、或输出不符合 C19 的报告？ | 合理输入下出现崩溃（未捕获异常）、退出码或报告与 spec 不符 |
| I6 | 只读（C20）与依赖（C21）在真实执行点是否成立，而不只在测试环境中成立？实现中是否有针对测试或夹具的特判？ | 真实运行时写入项目文件或依赖第三方包；存在测试特判 |
