# EG-S1 审查检查表（阶段 5，严格档，冻结）

> 冻结于派发 B1 之前（D-016）。Closure 不新增检查项；真正无法映射的重大问题报 CHECKLIST_GAP。
> 机械检查（ID 唯一、引用存在、覆盖关系、错误实现存在、地图指向）已由脚本完成，不在本表内。
> R1—R6 与 EG-S2 检查表相同；R7、R8 为严格档附加项（D-009）。

| ID | 问题 | 阻塞条件 |
|---|---|---|
| R1 | 每个条款是否忠实于它引用的决定，没有扩大、缩小或改变决定含义？ | 条款与所引决定原文冲突，或增加了决定没有的义务（D-006、D-011） |
| R2 | 是否存在未标出的实质选择（碰到 D-008 触碰面、却既无决定引用也未标 substantive 的内容），或引用的决定并不包含条款所写的内容？ | 发现未经用户决定的实质选择（D-011） |
| R3 | 每条验收的错误实现，是否真能被一个合理的测试区分出来？是否遗漏了更可能出现的错误实现？ | 某条款的全部错误实现都无法区分正确与错误实现，或明显更常见的错误被遗漏（D-010） |
| R4 | 是否遗漏影响结果的输入边界或失败路径？ | 合理输入下两个都符合 spec 的实现会给出不同的通过/失败结论（D-016） |
| R5 | 目标与非目标是否与 spec 地图及其他 spec 的边界一致？是否为未来预建了没有当前使用者的能力？ | 与其他 spec 的职责重叠或留出空档（D-007） |
| R6 | 条款编号交叉引用、术语、输出字段是否前后一致？ | 不一致会导致实现者无法确定行为（D-016） |
| R7 | 影响登记是否完整：本 spec 触碰的其他 spec、共用文件、既有工件与 0.1.0 合同是否都已列出，处理方式是否不改变其他 spec 已冻结的行为？ | 漏登记的影响会迫使已冻结的 spec（如 EG-S2）改变行为，或两份 spec 对同一文件给出冲突要求（D-009 严格档） |
| R8 | 崩溃、并发、超时三类故障是否都有验收，故障后的仓库状态（HEAD、暂存区、工作区、锁文件）是否被明确规定且可被测试观察？ | 某类故障下，两个都符合 spec 的实现会留下不同的仓库状态（D-009 严格档） |

裁定：PASS / FAIL / NEEDS_USER_DECISION。每条 BLOCKER/MAJOR 必须映射本表一项，并给出原文、依据和反例。
